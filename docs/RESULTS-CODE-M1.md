## How it was measured

`scripts/eval-code-model.mjs` on the held-out gold plans (never used for training). Each
reference project passed build, Blueprint, locator and runtime checks; each component is
then removed and regenerated by the candidate with the rest of the project as context.

- **A** - first attempt passes: build, Blueprint, locator, live route check.
- **B** - passes after the normal build-repair rounds (the candidate does the repairs).
- **C** - the candidate writes every backend and security component of the project.
- **D** - the live route check alone.

Both candidates ran on the same server, weights and hardware (`training/code/modal_eval.py`);
the adapter was the only difference.

## Results - backend and security (46 components, 25 reference projects)

| | Plain Qwen2.5-Coder-7B | **Trained adapter** | Change |
|---|---|---|---|
| **A** first attempt | 41.3% | **87.0%** | **+45.7 pts** |
| **B** after repair | 58.7% | **87.0%** | +28.3 |
| **C** whole project | 28.0% | **80.0%** | +52.0 |
| D (route check) at A | 41.3% | 87.0% | - |
| Backend (n = 36), A | 41.7% | 86.1% | +44.4 |
| Security (n = 10), A | 40.0% | 90.0% | +50.0 |

All six of the adapter's failures are build failures; none failed a live route.

**Correction (2026-10-01): the Blueprint and locator checks in these runs were vacuous.**
They read only each plan's `constraints`, which are business rules; none of the 14 in the
26 reference plans compiled, so no rule was evaluated. Re-checked afterwards against rules
compiled from each plan's `dependsOn` (the check the pipeline now runs, `plan-rules.ts`):
0 violations and 0 locator findings in all 131 first-attempt candidate files of both
models, the 26 references and the 91 teacher projects, while planted faults were caught
144/144 (imports) and 144/144 (runtime lookups) with 0/58 false alarms. So A is unchanged;
B and C were not re-scored (their files were not kept). Scripts:
`presentations/paper/reference/analysis/`.

## Results - frontend and database

First 20 components (`--domains=frontend,database --skip-c --limit=20`), same server and
references. The route check (D) does not apply: these files own no API route. C was skipped.

| | Plain Qwen2.5-Coder-7B | **Trained adapter** | Change |
|---|---|---|---|
| **A** first attempt | 20.0% | **55.0%** | +35.0 pts |
| **B** after repair | 40.0% | **85.0%** | +45.0 |
| Frontend (n = 11), A / B | 36.4% / 63.6% | 72.7% / 81.8% | +36.3 / +18.2 |
| Database (n = 9), A / B | 0.0% / 11.1% | 33.3% / 88.9% | +33.3 / +77.8 |

The gain holds for these domains too, even though they supplied most of the accepted
training files (frontend 168 and database 105 of 403). It is smaller on first attempt than
for backend and security, and repair matters more (database 33% → 89%). n = 20 is small:
treat these as direction, not precision.

## Caveats

- **Reference provenance.** Gemini's free daily quota covered only 5 gold plans, so 23 of
  the 26 reference projects were built by the same 32B teacher that wrote the training
  data. The candidate regenerates one component inside a teacher-written project, which may
  favour the adapter. The Gemini-built references hold only 2 of the 46 components (adapter
  2/2, plain model 1/2) - too few to test the effect either way.
- **Sample size.** 46 components; a ±7-point swing is within noise at this n.
- **One teacher, one round.** No second training run (C4) was needed or made.
